OBJECTIVE
Implement a new multiplayer mini game named KALADONT for Casual Mode / AMUSEMENT PARK.

This is NOT a simple two-player word-chain toy. It is a server-authoritative multiplayer elimination game with a lobby, fixed turn order, 60-second turns, mandatory player voting on submitted words, eliminations, spectators, and a last-player-standing winner.

CORE ARCHITECTURE
- KALADONT exists only in CASUAL / AMUSEMENT PARK.
- It must not affect Battle Mode scoring, WOMF, Final Solution logic, battle timers, battle streaks, or other battle state.
- Any online Little Hero may create a Kaladont lobby.
- The creator is the lobby owner only for setup/start/cancel purposes. They receive no gameplay advantage.
- Other currently-online Little Heroes may voluntarily JOIN the lobby from the mini-game invitation UI.
- A player must explicitly join; nobody is force-added.
- Once the creator starts the game, joining closes.
- Server randomizes the initial turn order once at game start.
- Turn order remains fixed for the match. Eliminated players are skipped automatically.
- Eliminated players become spectators for the rest of that Kaladont match.
- The match continues until exactly one active player remains.
- That final player is declared the winner.

LOBBY FLOW
1. Player opens Mini Games.
2. Chooses KALADONT.
3. They may:
   - CREATE ROOM
   - see/join an existing open Kaladont lobby if one exists
4. Lobby should clearly show:
   - creator

   - LEAVE button for joined non-creator
   - CANCEL LOBBY for creator
5. Only online players may join.
6. Starting should require at least 2 players.
7. Once started, lobby is locked.

GAME LOOP
At game start:
- Server randomizes joined players into a fixed turn order.
- Choose the first player according to that randomized order.
- Each turn lasts exactly 60 seconds.
- No skipping turns.
- Only the current active player may submit a word.
- All other active players are waiting/judging.
- The UI must prominently show:
  CURRENT PLAYER
  REQUIRED PREFIX
  TIMER
  TURN ORDER
  ELIMINATED / SPECTATOR PLAYERS
  CURRENT WORD INPUT for the active player only

WORD CHAIN RULE
- Each accepted word determines the required prefix for the next turn using its LAST TWO LETTERS.
- Next submitted word must begin with those exact two letters.
- Comparison should be case-insensitive.
- Trim whitespace.
- Normalize safely for Serbian Latin/Cyrillic only if the existing app already has a preferred text normalization strategy. Do not invent aggressive transliteration unless necessary.
- A submitted word may not repeat any previously ACCEPTED word in the same Kaladont match.
- Only accepted words enter the used-word history.
- Rejected words do not advance the chain and do not enter used-word history.
- Empty submission is invalid.
- Only one submission per turn.
- Submission becomes immutable immediately after send.

FIRST TURN
For the very first player, there is no previous word.
Use a clean server-defined opening rule:
- first player may submit any valid non-empty word.
- after it is accepted, its last two letters become the required prefix for the next player.

AUTOMATIC SERVER VALIDATION
The server judges STRUCTURE only:
- is it the current player?
- is the match active?
- is it still within the 60-second turn?
- non-empty?
- correct required two-letter prefix, if one exists?
- not previously used?
- valid message length / safe input?
Do NOT attempt to determine whether the submitted string is a legitimate Serbian word using a dictionary.

LANGUAGE LEGITIMACY IS DECIDED BY PLAYERS.

TRIBUNAL / VOTING PHASE
After a structurally valid submission:
- Freeze/end the player's 60-second turn timer.
- Enter a TRIBUNAL phase.
- Display the submitted word prominently to every living participant.
- Every living participant, INCLUDING THE PLAYER WHO SUBMITTED THE WORD, gets a vote:
  ACCEPT
  REJECT
- Each living player may vote exactly once.
- Votes cannot be edited after submission.
- Voting window: 15 seconds.
- Voting should be anonymous while voting is open.
- Once resolved, reveal who voted ACCEPT and who voted REJECT.
- Eliminated spectators do not vote.
- Players who fail to vote before the voting window ends count as ACCEPT.

VERDICT
Use simple majority over the final vote set after timeout/autofill.

- ACCEPT votes > REJECT votes:
  WORD ACCEPTED
  current player survives
  word is added to accepted-word history
  required prefix becomes final two letters of that accepted word
  advance to next living player in fixed turn order

- REJECT votes > ACCEPT votes:
  WORD REJECTED
  current player is ELIMINATED
  rejected word is NOT added to accepted-word history
  chain remains based on the previous accepted word
  advance to next living player

- TIE:
  WORD ACCEPTED

Important principle:
Silence cannot execute another player.
Therefore missing votes count as ACCEPT.

TURN TIMEOUT
If the current player fails to submit within 60 seconds:
- instant elimination
- no tribunal
- chain remains unchanged
- advance to next living player

STRUCTURAL INVALID ANSWER
If the current player submits something structurally invalid, such as:
- wrong prefix
- duplicate accepted word
- empty/invalid submission
Then:
- treat it as a failed answer
- eliminate that player immediately
- no tribunal required
- chain remains unchanged
- show the reason publicly
This prevents repeated garbage submissions during the same turn.

KALADONT SPECIAL MOVE
Retain the classic KALADONT identity as a tactical special case.

If a player legally submits the exact word:
KALADONT

and it satisfies the currently required prefix:
- automatically ACCEPT it
- no tribunal
- add KALADONT to accepted-word history
- the next living player in turn order is immediately eliminated because the resulting prefix "NT" is treated as terminal for this game
- then continue from the next surviving player

Do not rely on dictionary lookup for the "NT" condition. This is an explicit game rule.

If using KALADONT would leave only one player alive, resolve the winner immediately.

ELIMINATION
When a player is eliminated:
- visibly mark them eliminated in the Kaladont UI
- remove them from future active turns
- keep them in the room as a spectator
- preserve their ability to watch the game
- they must not submit words or tribunal votes
- show public elimination reason:
  TURN TIMEOUT
  INVALID PREFIX
  DUPLICATE WORD
  WORD REJECTED
  KALADONT KILL
  or another precise structural reason

WIN CONDITION
When one active player remains:
- stop all timers
- close any open tribunal
- declare:
  LAST LITTLE HERO STANDING
  <PLAYER NAME> WINS KALADONT
- show final standings / elimination order if practical.
- preserve the result long enough for all connected players to see it.
- allow the lobby owner or UI to return everyone to the Mini Games menu / Casual chat cleanly.
- no Battle Mode points or WOMF changes.

DISCONNECT / RECONNECT RULES
Design this deliberately and server-authoritatively.

During lobby:
- disconnected players should not remain eligible to start unless they reconnect.
- if the creator disconnects, transfer lobby ownership to the next joined online player, or close the lobby if nobody remains.

During active game:
- if the current player disconnects and does not reconnect before their 60-second turn expires, they are eliminated by timeout.
- if a non-current player disconnects, keep them in the game until their turn unless the architecture strongly favors immediate elimination; prefer allowing reconnect where reasonable.
- if a player disconnects during tribunal, their missing vote resolves as ACCEPT at tribunal timeout.
- reconnecting players should rehydrate the exact current Kaladont state and resume as player or spectator as appropriate.

SERVER AUTHORITY
This entire game must be server-authoritative.
The client must never decide:
- turn order
- current player
- timer expiration
- accepted-word history
- required prefix
- vote count/result
- eliminations
- winner
- Kaladont special-kill resolution

Client is presentation + input only.
